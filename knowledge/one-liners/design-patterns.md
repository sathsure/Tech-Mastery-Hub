# SOLID & Design Patterns — One-liners

> The most asked questions, each answered in one sentence.

1. **What is the Single Responsibility Principle?** — A class should have only one reason to change.
2. **What is the Open/Closed Principle?** — Code should be open for extension but closed for modification.
3. **What is the Liskov Substitution Principle?** — A subclass must work anywhere its parent class is used.
4. **What is Interface Segregation?** — Prefer many small interfaces over one large one.
5. **What is Dependency Inversion?** — High-level code should depend on abstractions, not concrete classes.
6. **What is a Singleton?** — A class that has only one instance with a global access point.
7. **What is a Factory?** — An object or method that creates objects without exposing which class is used.
8. **What is a Builder?** — A pattern that constructs a complex object step by step.
9. **What is an Adapter?** — A wrapper that makes one interface work like another.
10. **What is a Decorator?** — A wrapper that adds behaviour to an object without changing its class.
11. **What is a Proxy?** — A stand-in that controls access to another object.
12. **What is a Facade?** — A simple interface over a complex subsystem.
13. **What is the Strategy pattern?** — Swappable algorithms behind a common interface.
14. **What is the Observer pattern?** — Subscribers are notified automatically when a subject changes.
15. **What is the Template Method pattern?** — A base class defines the steps and subclasses fill in some of them.
16. **What is Chain of Responsibility?** — A request passes through a chain of handlers until one handles it.
17. **What is the Command pattern?** — Wrapping an action as an object so it can be queued or undone.
18. **What is the State pattern?** — An object changes its behaviour when its internal state changes.
19. **Composition vs inheritance?** — Composition builds behaviour from other objects; inheritance reuses a parent class — prefer composition.
20. **What are DRY, KISS and YAGNI?** — Don't repeat yourself, keep it simple, and don't build what you don't need yet.
