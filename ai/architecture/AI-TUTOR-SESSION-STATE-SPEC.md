# AI Tutor Session State Specification`n`n## 1. Purpose`n`nSession state provides continuity for learning, interview, practice, and navigation without becoming repository authority.`n`n## 2. State Model`n`nSession may contain identifier, current topic, canonical concept, learning level, requested depth, learning mode, previously explained concepts, interview/practice state, questions, responses, knowledge gaps, and progression.`n`n## 3. State Rules`n`nSession state is runtime state; it must not modify canonical repository knowledge; it cannot create knowledge relationships; repository retrieval remains authoritative; credentials must never be stored.`n`n## 4. Learning Continuity`n`nUse state to avoid repetition, increase depth, revisit gaps, adapt interview difficulty, and continue practice while retrieving authoritative repository evidence when required.`n`n## 5. Interview State`n`nTrack topic, difficulty, questions asked, responses, identified gaps, and progression.`n`n## 6. Failure Recovery`n`nIf session state is unavailable, continue when sufficient current context exists and retrieve repository context again when required. Do not infer persistent knowledge from missing state.`n`n## 7. Authority Boundary`n`nSession state influences teaching continuity only and never substitutes for repository content or the knowledge index.
