# AI Tutor Visual Runtime Specification`n`n## 1. Purpose`n`nVisuals are a first-class teaching capability. The runtime decides whether a visual improves comprehension and selects the appropriate source.`n`n## 2. Visual Decision`n`nQuestion -> Is visual useful? -> Repository visual -> Structured deterministic diagram -> Generated illustration`n`nIf no visual is useful, continue textual teaching.`n`n## 3. Repository Visual Selection`n`nPrefer a repository visual when it directly represents the concept, is sufficiently clear, is consistent with repository knowledge, and satisfies the requested visual purpose.`n`n## 4. Structured Diagram Selection`n`nPrefer deterministic diagrams for architecture, request flow, lifecycle, execution flow, data flow, dependency relationships, and component interactions.`n`n## 5. Generated Illustration Selection`n`nUse generated illustration when a custom conceptual representation provides greater teaching value and deterministic structure is not the primary requirement.`n`nGenerated visuals are answer-specific unless contributed through the governed workflow.`n`n## 6. Visual Plan Contract`n`nThe plan identifies visual usefulness, purpose, source type, source reference, explanation relationship, precision requirement, generation requirement, and accessibility description.`n`n## 7. Visual Safety`n`nDo not fabricate repository screenshots, present generated visuals as repository assets, expose secrets, bypass attribution, or generate decorative visuals without teaching value.
