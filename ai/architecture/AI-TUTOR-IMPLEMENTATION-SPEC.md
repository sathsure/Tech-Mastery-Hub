# AI Tutor Implementation Specification`n`n## 1. Purpose`n`nConverts the frozen AI Tutor implementation architecture into implementation-level contracts covering responsibilities, inputs, outputs, sequencing, boundaries, and testable invariants.`n`n## 2. Implementation Principles`n`n- Repository knowledge remains authoritative.`n- Runtime components are replaceable behind stable interfaces.`n- Read and write paths remain separate.`n- Visual output is a first-class teaching capability.`n- Repository retrieval precedes repository-backed explanation.`n- External knowledge remains distinguishable from repository knowledge.`n- User-provided material is untrusted until validated.`n- Security and governance failures fail closed for writes.`n- Only merged authoritative repository state becomes indexed knowledge.`n- Runtime behavior is observable and testable.`n`n## 3. Runtime Pipeline`n`n```text`nUser Query -> Intent Analyzer -> Retrieval Planner -> Knowledge Retriever -> Relationship Traversal -> Context Assembler -> Teaching Strategy Engine -> Visual Teaching Engine -> Example / Demonstration Engine -> Response Constructor -> Response Validator -> User Response`n``` `n`nWrite path:`n`n```text`nUser Material -> Security Gateway -> Content Validation -> Canonical Ownership -> Duplicate Detection -> Relationship Analysis -> Impact Analysis -> Feature Branch -> Tests -> Pull Request -> Human Approval -> Merge -> Re-index`n``` `n`n## 4. Component Contract Summary`n`n| Component | Input | Output | Boundary |`n|---|---|---|---|`n| Intent Analyzer | query + session | intent plan | no repository mutation |`n| Retrieval Planner | intent + session + index | retrieval plan | no invented relationships |`n| Knowledge Retriever | plan + index | evidence | index is not content |`n| Relationship Traversal | approved links | related evidence | no runtime relationship creation |`n| Context Assembler | evidence | source-aware context | preserve source identity |`n| Teaching Strategy Engine | intent + context | teaching plan | do not force strategies |`n| Visual Teaching Engine | plan + context | visual plan | no unnecessary generation |`n| Example Engine | topic + level | examples | distinguish generated examples |`n| Response Constructor | context + plans | response | preserve source boundaries |`n| Response Validator | response | validated response | reject invalid attribution |`n| Security Gateway | write request | security decision | fail closed |`n| Contribution Pipeline | validated request | PR/change lifecycle | no direct main mutation |`n| Re-indexer | merged repository | validated index | no unmerged authority |`n`n## 5. Core Invariants`n`n1. Repository-backed answers require repository evidence.`n2. The knowledge index identifies content but does not replace it.`n3. Runtime traversal uses approved relationships only.`n4. A visual plan explains why a visual is useful.`n5. Visual order is repository -> structured -> generated.`n6. Generated examples remain distinguishable from repository examples.`n7. Read requests cannot mutate authoritative state.`n8. Write requests cannot bypass security/governance.`n9. AI cannot approve its own repository change.`n10. Unmerged branches cannot become authoritative knowledge.`n11. Validation failures block invalid delivery or mutation.`n12. Audit events contain no secrets or credential values.`n`n## 6. Implementation Sequence`n`n### Phase A`nContracts, data models, validators.`n`n### Phase B`nRepository indexing and retrieval adapters.`n`n### Phase C`nRelationship-aware context assembly.`n`n### Phase D`nTeaching strategy and response construction.`n`n### Phase E`nVisual planning and visual source selection.`n`n### Phase F`nSession, interview, and practice state.`n`n### Phase G`nGoverned contribution workflow.`n`n### Phase H`nEnd-to-end runtime and contract tests.`n`n## 7. Minimum Definition of Done`n`nRepository questions retrieve actual evidence; canonical concepts anchor retrieval; approved relationships expand context; source identity survives response construction; visual selection follows repository -> structured -> generated; responses pass validation; unknown topics are identified as gaps; reads cannot mutate state; writes fail closed; human approval precedes merge; merged state is re-indexed; automated tests cover runtime behavior.
